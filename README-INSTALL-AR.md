# نشر وتثبيت «وقتي بذكاء» — إصدار إصلاح التثبيت

## النشر على GitHub Pages

1. فك ضغط هذه الحزمة على جهازك. لا ترفع ملف ZIP نفسه إلى المستودع وتتوقع أن يستخرجه GitHub تلقائيًا.
2. ارفع محتويات المجلد بحيث يكون `index.html` و`manifest.webmanifest` و`service-worker.js` في مجلد النشر نفسه، وتكون مجلدات `icons/` بجوارها.
3. إذا كان النشر من مجلد `docs`، ضع الملفات كلها داخله. وإذا كان الموقع Project Pages، افتح رابط الموقع المنشور مع مسار المستودع، مثل `https://USERNAME.github.io/REPOSITORY/`، وليس رابط صفحة ملفات GitHub أو رابط ملف HTML في المستودع.
4. من إعدادات المستودع افتح **Settings → Pages** وتأكد من الفرع والمجلد اللذين يحتويان هذه الملفات، ثم انتظر اكتمال النشر.

المسارات داخل الإصدار نسبية، واختُبرت على مسار فرعي يحاكي Project Pages. بعد النشر تحقق من أن الصفحة الرئيسية و`manifest.webmanifest` و`service-worker.js` وأيقونتي `icons/icon-192.png` و`icons/icon-512.png` تفتح دون خطأ 404.

## التثبيت

- **Android:** افتح رابط Pages مباشرة في Google Chrome، وليس داخل نافذة متصفح مضمّن في تطبيق آخر. من قائمة ⋮ اختر **تثبيت التطبيق** أو **إضافة إلى الشاشة الرئيسية**. قد تختلف التسمية بحسب Chrome وإصدار Android.
- **iPhone وiPad:** افتح رابط التطبيق في Safari، ثم اضغط **مشاركة → إضافة إلى الشاشة الرئيسية**. لا تعتمد على زر التثبيت المخصص في متصفحات iOS الأخرى.
- **الكمبيوتر:** في Chrome أو Edge استخدم رمز التثبيت قرب شريط العنوان أو خيار التثبيت في قائمة المتصفح.

إذا لم تظهر نافذة التثبيت، اضغط زر **طريقة التثبيت** داخل التطبيق. غياب النافذة المخصصة لا يعني بالضرورة أن الموقع غير صالح؛ بعض المتصفحات أو أوضاع التصفح لا تدعم حدث التثبيت البرمجي، وقد يبقى التثبيت اليدوي متاحًا.

## بعد تحديث نسخة منشورة سابقًا

أغلق علامات تبويب التطبيق القديمة ثم أعد فتح رابط Pages وتحديثه. الإصدار يغيّر اسم cache لعامل الخدمة ليطلب ملفات النسخة الجديدة بدل الاعتماد على cache الإصدار السابق. لا تحذف بيانات المتصفح أو التطبيق إن كانت لديك مهام محفوظة إلا بعد تصدير نسخة احتياطية من داخل التطبيق.
